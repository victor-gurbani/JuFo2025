\section{Methodik und praktische Umsetzung}

Dieses Kapitel beschreibt die technische Architektur, Implementierung und das methodische Vorgehen des digitalen Kontrollsystems. Im Fokus steht die Verknüpfung von Hardware, skalierbarer Software-Infrastruktur und KI-Algorithmen zur Identitätsprüfung.

\subsection{Systemarchitektur}
\begin{figure}[htbp]
    \centering
    \includegraphics[width=0.8\textwidth,height=0.4\textheight,keepaspectratio]{figures/systemarchitektur.pdf}
    \caption{Systemarchitektur des digitalen Zugangs- und Auslasskontrollsystems}
    \label{fig:architecture}
\end{figure}

Das System nutzt ein entkoppeltes Client-Server-Modell für maximale Flexibilität. Wie in Abbildung \ref{fig:architecture} ersichtlich, besteht das Ökosystem aus einem Node.js-Backend, einer plattformübergreifenden Mobilanwendung (Frontend) und einer lokalen SQLite-Datenbank.

Das Backend basiert auf Express.js \cite{expressjs2023} und zentralisiert Geschäftslogik, Berechtigungsprüfung sowie Gesichtserkennung. Die Architektur folgt Clean-Code-Prinzipien \cite{martin2008clean}, während Node.js eine hohe Performance bei asynchronen Operationen wie dem Einlesen großer Bilddaten ermöglicht. Die Kommunikation erfolgt über eine zustandslose RESTful API, abgesichert durch JSON Web Tokens (JWT).

Das Frontend wurde mit React Native und dem Expo SDK \cite{reactnative2023, expo2023} entwickelt, um iOS und Android aus einer Codebasis zu bedienen. Die UI nutzt \textit{react-native-paper} für eine intuitive Bedienung. Rechenintensive Bildverarbeitung und neuronale Netze werden auf den Server ausgelagert, um die Hardwareanforderungen an die Endgeräte zu minimieren.

\subsection{RFID-Kartenmanagement und Berechtigungsmodell}
\begin{figure}[htbp]
    \centering
    \includegraphics[width=0.8\textwidth,height=0.4\textheight,keepaspectratio]{figures/rfid_workflow.pdf}
    \caption{Sequenzdiagramm des RFID-Kartenmanagements}
    \label{fig:rfid_workflow}
    \vspace{-1em}
\end{figure}

Die Identifikation erfolgt über die \textit{Unique Identifier} (UID) von RFID-Medien. Das rollenbasierte Berechtigungsmodell (RBAC) unterscheidet zwischen Schülern, Lehrkräften, Sicherheitspersonal und Administratoren.

Lehrkräfte definieren über ein Dashboard zeitlich begrenzte, einmalige oder rekursive Berechtigungen (z.\,B. wöchentliche Termine). Da Freigaben logisch an Profile und nicht an physische Karten gebunden sind, lassen sich RFID-Medien flexibel neu vergeben. Bei jedem Scan validiert das Backend die UID gegen hinterlegte Zeitfenster und Profile \cite{finkenzeller2015rfid}. Dieser Prozess automatisiert die Protokollierung in den \textit{accessLogs} und entlastet das Personal.

\subsection{Gesichtserkennungs-Pipeline}
\begin{figure}[htbp]
    \centering
    \includegraphics[width=0.8\textwidth,height=0.4\textheight,keepaspectratio]{figures/gesichtserkennung_pipeline.pdf}
    \caption{Ablauf der Gesichtserkennungs-Pipeline}
    \label{fig:face_pipeline}
\end{figure}

Eine biometrische Verifikationsschicht ergänzt die RFID-Identifikation. Die Pipeline umfasst vier Phasen:

\begin{enumerate}
    \item \textbf{Normalisierung:} Uploads (inkl. HEIC) werden mittels \textit{heic-convert} und \textit{sharp} \cite{sharp2023} serverseitig in PNG umgewandelt und auf $1024 \times 1024$ Pixel skaliert.
    \item \textbf{Gesichtsdetektion:} Das \textit{SSD MobileNet v1}-Modell lokalisiert Gesichter effizient und präzise.
    \item \textbf{Merkmalsextraktion:} Eine Landmarker-Erkennung (68 Punkte) und ein ResNet-basiertes neuronales Netz generieren einen 128-dimensionalen Merkmalsvektor (Face Descriptor) \cite{goodfellow2016deep}.
    \item \textbf{Abgleich:} Die Verifikation nutzt die euklidische Distanz zwischen aktuellem Snapshot und Referenzvektor. Ein Schwellenwert von $0,6$ balanciert FAR und FRR optimal \cite{vladmandic2023faceapi}.
\end{enumerate}

\subsection{Datenbankdesign und technische Persistenz}

Die dateibasierte SQLite-Instanz benötigt keinen separaten Serverprozess und eignet sich ideal für lokale Schulumgebungen \cite{sqlite2023}. Das Schema umfasst die Tabellen \textit{students}, \textit{teachers}, \textit{cards}, \textit{permissions} und \textit{accessLogs}. Fremdschlüssel sichern die referenzielle Integrität, sodass Berechtigungen zwischen Schülern, Karten und Lehrkräften jederzeit nachvollziehbar bleiben.

\subsection{Datenschutzkonzept und Datensicherheit} \label{subsec:konzept_datenschutz}
Das Konzept setzt die Anforderungen aus Kapitel \ref{subsec:datenschutz} durch architektonische und kryptografische Verfahren um:

\begin{itemize}
    \item \textbf{Lokale Persistenz:} Die Speicherung biometrischer Templates erfolgt ausschließlich auf dem schuleigenen Server. Dies verhindert Zugriff durch Drittanbieter und minimiert die Angriffsfläche.
    \item \textbf{Datenminimierung:} Das System unterstützt die reine Speicherung von 128-dimensionalen Merkmalsvektoren. Rohbilder können nach der Registrierung gelöscht werden, um eine Rekonstruktion biometrischer Daten auszuschließen.
    \item \textbf{Transportsicherheit:} Die Kommunikation nutzt TLS 1.3. Sensible Datenbankfelder können zusätzlich mittels AES-256 verschlüsselt werden.
    \item \textbf{Zugriffskontrolle (RBAC):} Schnittstellen und Logs sind streng reglementiert. Lehrkräfte sehen nur eigene Kurse; Sicherheitspersonal erhält nur für die aktuelle Prüfung notwendige Daten. Die Umsetzung folgt BSI-Empfehlungen für Webanwendungen \cite{bsisicherheitscheck}.
\end{itemize}

Diese Maßnahmen gewährleisten ein Schutzniveau gemäß BayEUG und BayDSG \cite{bayeug, baydsg} und belegen, dass Sicherheit und Datenschutz lokal vereinbar sind.
